# API Documentation

This document provides a comprehensive overview of the API endpoints, including authentication, request formats, and expected responses. For an interactive experience, you can also use the Swagger UI available at `/api/docs` when the application is running.

---

## Authentication

The API uses JSON Web Tokens (JWT) for authentication. To access protected routes, you must include a valid JWT in the `Authorization` header of your request.

**Format:** `Authorization: Bearer <your_token>`

### 1. Register a New User

Creates a new user account.

- **Endpoint:** `POST /users/register`
- **Authentication:** None
- **Request Body:**

```json
{
  "email": "farmer@example.com",
  "first_name": "John",
  "last_name": "Doe",
  "phone_number": "+1234567890",
  "password": "strongpassword123",
  "date_of_birth": "1990-01-15",
  "gender": "male"
}
```

### 2. Log In

Authenticates a user and returns a JWT.

- **Endpoint:** `POST /auth/login`
- **Authentication:** None
- **Request Body:**

```json
{
  "phone_number": "+1234567890",
  "password": "strongpassword123"
}
```

- **Successful Response:**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

## Asset Management (`/api/assets/kit`)

All endpoints in this section require authentication.

### Create a New IoT Kit

- **Endpoint:** `POST /api/assets/kit`
- **Description:** Registers a new IoT kit and creates a default configuration for it. The `kit_id` is automatically generated by the server.
- **Request Body:**

```json
{
  "location_name": "North Field, Zone A",
  "crop_type": "Maize",
  "latitude": -1.17,
  "longitude": 36.95,
  "reading_interval_active_min": 5,
  "reading_interval_idle_min": 30
}
```

### Get All Kits

- **Endpoint:** `GET /api/assets/kit`
- **Description:** Retrieves a list of all active IoT kits owned by the authenticated user.

### Get a Single Kit

- **Endpoint:** `GET /api/assets/kit/:kitId`
- **Description:** Retrieves a single IoT kit by its ID.

### Update a Kit

- **Endpoint:** `PUT /api/assets/kit/:kitId`
- **Description:** Updates the location or crop type for a specific kit.
- **Request Body:** (All fields are optional)

```json
{
  "location_name": "Greenhouse 3",
  "crop_type": "Tomatoes"
}
```

### Decommission a Kit (Soft Delete)

- **Endpoint:** `DELETE /api/assets/kit/:kitId`
- **Description:** Sets the `is_active` flag for a kit to `false`. The kit's historical data is preserved.

### Permanently Delete a Kit

- **Endpoint:** `DELETE /api/assets/kit/:kitId/permanent`
- **Authentication:** Required (Admin Only)
- **Description:** Permanently deletes a kit and all its associated data.

## Configuration Management (`/api/assets/config`)

All endpoints in this section require authentication.

### Read Kit Configuration

- **Endpoint:** `GET /api/assets/config/:kitId`
- **Description:** Retrieves the complete configuration for a specific IoT kit.

### Update Kit Configuration

- **Endpoint:** `PUT /api/assets/config/:kitId`
- **Description:** Updates the configuration for a specific IoT kit. The `active_mode` field determines which automation rules are used.

- **Modes:**
  - `Manual`: The system will only irrigate based on the schedules defined in `manual_settings_json`.
  - `Sensor`: The system will automatically irrigate based on the moisture thresholds defined in `sensor_settings_json`.
  - `SmartWeather`: The system will use weather forecasts and AI predictions from `smart_weather_settings_json` to determine the irrigation schedule.

- **Request Body:**

```json
{
  "active_mode": "Sensor",
  "reading_interval_active_min": 5,
  "reading_interval_idle_min": 60,
  "low_moisture_threshold_pct": 30,
  "notifications_enabled": { "Offline": true, "Low Battery": true },
  "manual_settings_json": {
    "schedules": [
      { "time": "06:00", "duration_min": 30 },
      { "time": "18:00", "duration_min": 45 }
    ]
  },
  "sensor_settings_json": {
    "start_threshold_pct": 40,
    "stop_threshold_pct": 75
  },
  "smart_weather_settings_json": {
    "rain_threshold_mm": 5,
    "ai_sensitivity": "medium"
  },
  "emergency_irrigate": "AUTO"
}
```

- **`emergency_irrigate` Field:**
  - `ON`: Forces irrigation to be on, overriding all other settings.
  - `OFF`: Forces irrigation to be off, overriding all other settings.
  - `AUTO`: Allows the system to control irrigation based on the `active_mode`.

## Sensor Data (`/api/data`)

### Ingest Sensor Data

- **Endpoint:** `POST /api/data/ingest`
- **Authentication:** None (This endpoint is called by the IoT devices themselves)
- **Description:** Allows IoT kits to push new sensor readings to the database.
- **Request Body:**

```json
{
  "kit_id": "KIT-12345",
  "timestamp": "2025-11-06T10:00:00Z",
  "moisture": 55.5,
  "temperature": 22.3,
  "nitrogen": 120,
  "phosphorus": 50,
  "potassium": 80,
  "ph": 6.5,
  "battery": 95,
  "signal": 88,
  "firmware": 1.2,
  "ec": 1.5
}
```

### Get Latest Sensor Data

- **Endpoint:** `GET /api/data/live/:kitId`
- **Authentication:** Required
- **Description:** Retrieves the most recent sensor reading for a specific kit.

### Get Historical Sensor Data

- **Endpoint:** `GET /api/data/history/:kitId`
- **Authentication:** Required
- **Description:** Retrieves a time-series of sensor data for a specific kit within a date range.
- **Query Parameters:**
  - `from` (ISO 8601 Date String, e.g., `2025-11-01T00:00:00Z`)
  - `to` (ISO 8601 Date String, e.g., `2025-11-06T23:59:59Z`)

### Get Dashboard Summary

- **Endpoint:** `GET /api/data/summary`
- **Authentication:** Required
- **Description:** Retrieves the latest sensor reading and metadata for all active kits owned by the user in a single response. This is the recommended endpoint for populating a dashboard view.

## MQTT Integration

The application uses an MQTT broker for real-time, two-way communication between the server and the IoT devices.

### Device Control (Server-to-Device)

When a user sends a control command via the API, the server publishes a message to a specific MQTT topic that the device is subscribed to.

- **Topic Format:** `control/<kit_id>`
- **Example Topic:** `control/KIT-12345`
- **Payload:**

```json
{
  "is_irrigating": true
}
```

### Sensor Data Ingestion (Device-to-Server)

Devices publish their sensor readings to a specific MQTT topic. The server subscribes to this topic to ingest the data and save it to the database.

- **Topic:** `sensor/data`
- **Payload:** (Same as the `POST /api/data/ingest` endpoint)

```json
{
  "kit_id": "KIT-12345",
  "timestamp": "2025-11-06T10:00:00Z",
  "moisture": 55.5,
  "temperature": 22.3,
  "nitrogen": 120,
  "phosphorus": 50,
  "potassium": 80,
  "ph": 6.5,
  "battery": 95,
  "signal": 88,
  "firmware": 1.2,
  "ec": 1.5
}
```

### Configuration Updates (Server-to-Device)

When a kit's configuration is updated via the API, the server publishes the new configuration to a specific MQTT topic that the device is subscribed to.

- **Topic Format:** `config/<kit_id>`
- **Example Topic:** `config/KIT-12345`
- **Payload:** (The full `KitConfiguration` object)

```json
{
  "active_mode": "Sensor",
  "reading_interval_active_min": 5,
  "reading_interval_idle_min": 60,
  "low_moisture_threshold_pct": 30,
  "notifications_enabled": { "Offline": true, "Low Battery": true },
  "manual_settings_json": {},
  "sensor_settings_json": { "start_threshold_pct": 40, "stop_threshold_pct": 75 },
  "smart_weather_settings_json": {}
}
```

## Advisory Workflow (`/api/iot`)

The advisory API enables asynchronous decision-making for IoT devices. The devices upload data, an external analyzer (e.g., Raspberry Pi) retrieves pending data and submits a decision, and finally, the device fetches the decision.

### 1. Get Pending Analysis

Retrieves a list of sensor data records that have been uploaded but not yet analyzed (`advisory` is null). This endpoint is intended for the analysis service.

- **Endpoint:** `GET /api/iot/analysis/pending`
- **Authentication:** None (Public)
- **Response:** Array of `SensorData` objects.

### 2. Submit Advisory Decision

Updates a specific sensor data record with an advisory decision. This endpoint is intended for the analysis service after processing the data.

- **Endpoint:** `PUT /api/iot/analysis/:dataId`
- **Parameters:**
  - `dataId`: The ID of the sensor data record (from the pending list).
- **Authentication:** None (Public)
- **Request Body:**

```json
{
  "advisory": "IRRIGATE"
}
```

The advisory string can be any decision value or JSON string needed by the device (e.g., "WAIT", "IRRIGATE", " Fertilize").

### 3. Get Latest Advisory for Kit

Retrieves the latest advisory decision for a specific kit. This endpoint is intended for the IoT device to know what action to take.

- **Endpoint:** `GET /api/iot/advisory/:kitId`
- **Parameters:**
  - `kitId`: The unique identifier of the IoT kit.
- **Authentication:** None (Public)
- **Response:** The most recent `SensorData` object that contains a non-null advisory.
